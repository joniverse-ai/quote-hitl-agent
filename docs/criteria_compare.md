# 멈춤 기준 검증 — 규칙 모드 vs LLM 모드

같은 정답 라벨(R1~R5)로, 추출·등급 판단을 규칙(mock)으로 할 때와 LLM(gpt-4o-mini)으로 할 때를 비교했다.
멈춤 기준은 같다: **공급가 500만 원 초과 · 별도 협의 항목 · 등급 무리 불일치 · 표준 밖 조건 · 검수 실패 · 범위 밖 작업**.

| 세트 | 모드 | 개입률 | 놓침 | 헛멈춤 | 라우팅 오류 | 놓친 건 / 헛멈춤 건 |
|---|---|---|---|---|---|---|
| 개발용 31건 (기준을 만들 때 씀) | 규칙 | 52% (15/29) | 0 | 0 | 0 | - |
| 개발용 31건 | LLM | 52% (15/29) | 1 | 1 | 0 | 놓침 N13 · 헛멈춤 N03 |
| **검증용 10건 (기준을 정한 뒤 씀)** | 규칙 | 22% (2/9) | **4** | 0 | **1** (H08) | 놓침 H01, H03, H04, H09 |
| **검증용 10건** | LLM | 70% (7/10) | **0** | 0 | 0 | - |

## 읽는 법
- **규칙 모드는 개발용에선 완벽하지만 검증용에서 무너진다.** 키워드와 다른 표현("사진도 찍어", "영어 버전", "누끼", "조금 저렴하게")을 못 알아듣는다. 개발용의 0은 과적합이었다.
- **LLM 모드는 검증용에서 놓침 0.** 돌려 말한 표현을 문맥으로 잡는다. 대신 LLM 도 '급하게 필요합니다'를 희망 일정으로만 읽는 등 확실한 표현을 흘리는 경우가 있어, **규칙 키워드를 안전망으로 합쳤다(합집합)**. 키워드 목록은 검증 세트를 만들기 전에 정해 둔 것이다.
- 남은 오차 두 건은 성격이 다르다.
  - **N03 헛멈춤**: LLM 이 근거 없이 '신규 S'(조사·시안 3종)로 올려 잡아 공급가가 620만 원이 됐다. 과대 산정 → 사람이 보게 되는 **안전한 방향의 오류**다.
  - **N13 놓침**: 정답 라벨은 'R3 등급 모호'인데, LLM 은 3표 모두 '파생 B'로 판단했다. 단가표 등급 기준에 "기존 디자인의 시리즈 파생 = 파생"이 그대로 있어 **LLM 판단이 맞고 라벨이 틀렸을 수 있다.** 결과를 본 뒤 라벨을 고치면 편향이 되므로 그대로 두고 실장님 검토 항목으로 남긴다.

## 한계 (정직하게)
- 데이터가 작다(41건). 테스트 문장과 정답 라벨을 같은 사람이 썼다.
- 검증 세트가 완전히 깨끗하지 않다. H01 문장을 LLM 연결 확인에 한 번 썼고, 검증 세트의 실패를 본 뒤 추출 프롬프트에 '다른 말로 표현한 경우도 포함' 규칙을 넣었다 (검증 세트의 표현 자체는 프롬프트에 넣지 않았다).
- LLM 결과는 실행할 때마다 조금씩 달라질 수 있다 (등급 투표는 온도 0.8).
- 그래서 이 표는 "기준이 맞다"는 증명이 아니라 **"어느 기준이 어떤 위험을 막는지, 어디서 새는지"를 보여 주는 도구**로 쓴다. 실제 메일이 쌓이면 같은 스크립트로 다시 잰다.

## 다시 재기
```bash
python evaluate.py                 # 개발용, 키가 있으면 LLM 모드
python evaluate.py holdout         # 검증용
python evaluate.py holdout --mock  # 규칙 모드로
```
상세 결과: `criteria_eval_{dev|holdout}_{mock|llm}.md`
